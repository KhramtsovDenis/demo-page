# Jira Sync Requirements

Дата фиксации: 2026-09-04.

Этот документ описывает целевую логику синхронизации Jira -> недельный отчет Healbe и критерии проверки. Его нужно читать перед доработкой `weekly-reports/jira_sync_lab.html`, `assets/jira-sync-lab.js` и `assets/weekly-workboard.js`.

## Цель

Сократить ручное заполнение недельного отчета.

## Среда разработки

Jira-синхронизацию сначала делать только в тестовой среде.

Правила:

- боевой сайт не менять до успешного тестового прогона;
- все новые сценарии сначала проверять в `weekly-reports/jira_sync_lab.html`;
- переносить механику в боевой отчет только после проверки кнопок, текста, мобильной версии и логики данных;
- если тестовая логика спорная, исправлять ее в Lab, а не в production.

Целевой сценарий:

1. Пользователь нажимает `Добавить новую неделю`.
2. Платформа создает новую неделю из предыдущей по уже существующей логике.
3. Пользователь просит Codex собрать Jira-снимок за отчетную неделю.
4. В новом отчете пользователь нажимает `Загрузить Jira-снимок`.
5. Данные из Jira появляются прямо в отчете как слой предлагаемых изменений.
6. Пользователь проверяет изменения в карточках задач, откатывает лишнее кликом по кубику изменения и сохраняет только нужное.
7. После ручной доработки пользователь может скачать документ `Что обновить в Jira`.

Главный принцип: Jira-снимок не заменяет отчет молча. Он предлагает изменения и подсвечивает их в рабочем интерфейсе отчета.

## Базовые правила

- Скрытые, архивные и завершенные задачи не участвуют в Jira-синхронизации.
- Пустые значения из Jira не должны затирать заполненные поля отчета.
- Текстовые поля не перезаписывать автоматически.
- Если в отчете ключ задачи не совпадает с Jira, лучше исправить ключ в отчете.
- Большую таблицу соответствий ключей не делать.
- Исключение по ключам: `РУ (RU-*)`. Для этой строки отчета нужно собирать все подходящие задачи `RU-*`.
- `SPBSU40-1` / Грант СПБГУ не менять автоматически по статусу.
- Спорные Jira workflow-переходы не выполнять без ручного решения.

## Что брать из Jira

Можно подтягивать как обычные изменения:

- статус задачи;
- дату релиза;
- дату закрытия для завершенных задач;
- часы по согласованным людям;
- готовность/прогресс, если он рассчитан по понятному правилу;
- контрольные точки из дочерних или связанных Jira-задач.

Можно брать только как подсказку:

- комментарии за отчетную неделю для поля `Сделано за неделю`;
- описание задачи;
- блокеры и зависимости для поля рисков;
- названия задач, если в отчете уже есть более человекочитаемое название.

## Статусы

Реальные статусы, которые уже встречались в Jira Healbe:

- `Backlog`;
- `S4D`;
- `В работе`;
- `Проверка`;
- `Тестирование`;
- `DoD Review`;
- `ON HOLD`;
- `Blocked`;
- `Отказ`;
- `Открыто повторно`.

Нормализация для отчета:

- `Backlog` -> `discovery`;
- `S4D` -> `planned` или `in-progress`, нужно проверять по конкретному проекту;
- `В работе` -> `in-progress`;
- `Проверка` -> `test`;
- `Тестирование` -> `test`;
- `DoD Review` -> `test`;
- `ON HOLD` -> `paused`;
- `Blocked` -> `risk`;
- `Отказ` -> не применять автоматически, показывать предупреждение;
- `Открыто повторно` -> показывать предупреждение.

Правила:

- для системного анализа брать только часы согласованных людей;
- для `РУ (RU-*)` собирать worklog по всем задачам `RU-*`;

## Комментарии

Комментарии нужны не как сырой импорт, а как материал для подсказки.

Правила:

- брать обычные Jira-комментарии без специальной метки;
- период: даты отчетной недели;
- брать только комментарии по активным задачам отчета;
- не вставлять комментарии напрямую в `Сделано за неделю`;
- собирать из комментариев короткую подсказку в стиле отчета;
- если `Сделано за неделю` пустое, дать кнопку `Вставить подсказку`;
- если поле уже заполнено, показать подсказку рядом и не заменять текст молча.

## Контрольные точки

Источник:

- дочерние Jira-задачи;
- связанные Jira-задачи;
- текущие контрольные точки отчета как база.

Правила:

- если точка уже есть в отчете и совпадает по названию или ключу, предложить обновить дату, статус или процент;
- если в Jira появилась новая дочерняя/связанная задача, предложить добавить новую контрольную точку;
- если в отчете есть точка, а в Jira ее нет, не удалять автоматически;
- дата финальной точки для активной задачи берется из плановой даты релиза;
- дата финальной точки для закрытой задачи может брать дату закрытия Jira;
- дата промежуточной точки берется из due date / target date подзадачи, если есть;
- если даты у подзадачи нет, оставить текущую дату отчета или показать точку без даты.

Процент контрольной точки считать по связке:

- тип контрольной точки из названия;
- реальный Jira-статус.

Примерная логика:

- исследование в работе -> около 20%;
- PRD / требования в работе -> около 30%;
- UX/UI / дизайн в работе -> около 45%;
- системный анализ в работе -> около 60%;
- разработка в работе -> около 70%;
- проверка / тестирование -> около 90%;
- готово / закрыто -> 100%;
- `ON HOLD` -> не менять процент, показать паузу.

Проценты являются расчетными, поэтому должны подсвечиваться как предложение, а не как абсолютная истина.

## Интерфейс в отчете

Нужен не отдельный тяжелый предпросмотр, а слой изменений внутри текущего отчета.

Требования:

- после загрузки Jira-снимка измененные поля подсвечиваются прямо в карточках задач;
- рядом с измененным полем появляется кубик/бейдж `Jira`;
- клик по кубику откатывает именно это изменение;
- откат одного изменения не должен сбрасывать остальные изменения задачи;
- должна быть возможность откатить все изменения из Jira-снимка;
- после `Принять изменения` подсветка исчезает, а текущий отчет становится новой базой;
- подсказка для `Сделано за неделю` показывается рядом с полем и вставляется только по кнопке;
- новые контрольные точки из Jira показываются как предложенные, с действиями `Добавить` и `Скрыть`;
- изменения по статусам, датам, часам и контрольным точкам должны быть визуально разными или ясно подписанными.

## Кнопки

Обязательные кнопки и действия:

- `Добавить новую неделю` - создает неделю из предыдущей, очищает недельные поля и сохраняет активные задачи.
- `Загрузить Jira-снимок` - открывает выбор JSON-файла и применяет его как слой предложений.
- `Откатить Jira-изменения` - убирает все изменения из последнего Jira-снимка.
- Кубик `Jira` рядом с полем - откатывает конкретное изменение.
- `Вставить подсказку` - переносит собранный текст из комментариев Jira в поле `Сделано за неделю`.
- `Добавить` у предложенной контрольной точки - добавляет точку в отчет.
- `Скрыть` у предложенной контрольной точки - убирает предложение из текущего просмотра.
- `Принять изменения` - делает текущую версию отчета новой базой.
- `Скачать изменения` - сохраняет patch-файл для передачи владельцу отчета.
- `Скачать документ для Jira` - формирует список полей, где отчет новее Jira.

## Документ "Что обновить в Jira"

После ручных правок отчет должен уметь скачать файл со списком обратных расхождений.

Формат строки:

- задача;
- Jira-ключ;
- поле;
- значение в Jira;
- значение в отчете;
- рекомендация: обновить Jira / проверить вручную / игнорировать.

Документ нужен, если:

- в отчете дата релиза новее Jira;
- в отчете статус отличается от Jira;
- в отчете есть контрольная точка, которой нет в Jira;
- в отчете заполнено `Сделано за неделю`, а в Jira нет комментариев за неделю;
- в отчете есть часы, а Jira worklog пустой или меньше ожидаемого.

## Критерии проверки

Функциональная проверка:

- новая неделя создается из предыдущей;
- недельные поля очищаются;
- активные задачи остаются активными;
- скрытые, архивные и завершенные задачи не попадают в синхронизацию;
- Jira-снимок загружается без ошибок;
- неверный JSON показывает понятную ошибку;
- JSON от другой недели не применяется молча;
- задачи без Jira-ключа показываются как проблема;
- `РУ (RU-*)` собирает несколько Jira-задач;
- пустые значения Jira не затирают отчет;
- текстовые поля не заменяются без подтверждения.

Проверка изменений:

- изменение даты релиза подсвечивается;
- изменение статуса подсвечивается;
- изменение часов подсвечивается;
- новая контрольная точка показывается как предложение;
- обновление существующей контрольной точки подсвечивается;
- комментарии недели превращаются в подсказку, а не сырой текст;
- клик по кубику `Jira` откатывает только одно поле;
- общий откат Jira-изменений возвращает состояние до загрузки снимка;
- `Принять изменения` убирает подсветку и обновляет базу;
- после принятия можно импортировать следующий patch без старых конфликтов.

Проверка кнопок:

- все кнопки нажимаются мышкой;
- все кнопки доступны с клавиатуры через Tab/Enter;
- кнопки не перекрываются другими элементами;
- кнопки не уезжают за экран на мобильной ширине;
- после клика видно, что действие выполнено: подсветка, сообщение, изменение поля или скачанный файл;
- повторный клик не ломает состояние и не создает дублей.

Проверка визуального формата:

- текст в полях полностью виден;
- длинные русские названия задач не вылезают из карточек;
- бейджи `Jira` не закрывают основной текст;
- список контрольных точек остается читаемым;
- подсказка из комментариев не превращается в огромную стену текста;
- на мобильной версии нет горизонтального скролла из-за новых блоков;
- на desktop и mobile видно, какое поле изменилось и откуда пришло изменение;
- цвет подсветки не конфликтует с текущими статусами отчета.

Проверка логики часов:

- учитываются только согласованные сотрудники;
- Сергей Волков исключен;
- системный анализ считается только по согласованным людям;
- часы по `RU-*` суммируются корректно;
- часы скрытых/архивных/завершенных задач не учитываются;
- итоговая цифра совпадает с ручной проверкой на 2-3 задачах.

Проверка обратного документа для Jira:

- файл скачивается;
- в файле нет скрытых/архивных/завершенных задач;
- для каждого расхождения указаны Jira-значение и значение отчета;
- спорные статусы отмечены как `проверить вручную`;
- файл можно открыть обычным редактором или таблицей.

## MVP

Первый рабочий этап:

1. Загрузка Jira-снимка прямо в недельном отчете.
2. Подсветка изменений по датам, статусам и часам.
3. Откат конкретного изменения кликом по кубику.
4. Подсказка `Сделано за неделю` из комментариев.
5. Документ `Что обновить в Jira`.

Второй этап:

1. Контрольные точки из дочерних/связанных Jira-задач.
2. Расчет процента контрольной точки по типу точки и Jira-статусу.
3. Применение выбранных контрольных точек внутри отчета.

Третий этап:

1. Автоматический сбор Jira-снимка без ручного JSON.
2. Осторожная обратная запись в Jira после ручного подтверждения.
